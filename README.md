# Sommelier Academy

Русскоязычное приложение для изучения вина, крепкого алкоголя и пива.
React + TypeScript + Vite + Tailwind CSS + Lucide React + React Router.
Сервер и регистрация не нужны. Хостинг — GitHub Pages.

## Запуск

Нужны Node.js **22.14+** и npm.

```sh
npm install
npm run dev
```

Откройте адрес, который напечатает Vite. На Windows при блокировке `npm.ps1`
используйте `npm.cmd` вместо `npm`.

```sh
npm run validate
npm test
npm run build
npm run preview
```

`validate` проверяет структуру всей базы; `test` использует встроенный тестовый
раннер Node для проверки оценки ответов, очереди повторения, истории и данных.
`build` запускает TypeScript и создаёт статический `dist/`.

## Что работает

- Главная с актуальными показателями и четырьмя режимами.
- Обучение: категории, сложность, 10/20/50/100/все вопросы, объяснение после ответа.
- Экзамен: те же фильтры, выбор времени, окончательные ответы, разбор после завершения.
- Таймер экзамена использует абсолютное время и продолжает идти после закрытия вкладки.
- Повторение: вопросы с последним неверным ответом; правильное повторение убирает вопрос.
- База знаний: динамические категории, направления, поиск по темам, прогресс.
- Статистика, последние 100 занятий, разбор правильных, ошибочных и пропущенных ответов.
- Автосохранение текущего занятия, восстановление после обновления страницы.
- Экспорт/импорт JSON, подтверждение замены или удаления данных.
- Одиночный и множественный выбор, необязательные изображения, три уровня сложности.
- Адаптивная тёмная тема; мобильная навигация, состояния фокуса и reduced motion.

Включены **370 вопросов в 37 категориях: по 10 в каждой**. Есть базовые,
продвинутые и экспертные вопросы, в том числе с несколькими правильными ответами.
Каждый вопрос связан с официальными источниками: WSET, AWRI, отраслевыми
консорциумами, регуляторами и BJCP. Ссылки доступны после ответа в обучении
и в разборе завершённого экзамена. Это авторская учебная подборка по открытым
материалам, не копия закрытых экзаменов и не официальная программа сертификации.

## GitHub Pages

1. Создайте публичный репозиторий и загрузите проект в ветку `main`.
2. В репозитории откройте **Settings → Pages → Source → GitHub Actions**.
3. В **Actions** запустите `Check and deploy to GitHub Pages` или сделайте push.
4. После успешного workflow адрес появится в **Settings → Pages** и окружении `github-pages`.

Workflow сам определяет имя репозитория и передаёт корректный `VITE_BASE_PATH`.
Для репозитория `sommelier-academy` адрес будет
`https://USERNAME.github.io/sommelier-academy/`.
Для `USERNAME.github.io` используется корень `/`.
Навигация имеет вид `/#/learn`: HashRouter поддерживает обновление и прямые ссылки
на Pages без серверных rewrite. По умолчанию Vite собирает относительные пути `./`.
При настройке собственного домена установите в workflow `VITE_BASE_PATH=/`.

Сохраняйте `package-lock.json` вместе с изменениями зависимостей.
Если локальная ограниченная среда запрещает esbuild читать родительские каталоги
при загрузке конфигурации Vite, используйте `npm run build -- --configLoader runner`.
Сама сборка приложения и пути к ресурсам при этом не меняются.

## Добавление вопросов и архитектура

Подробная карта экранов, модулей, формата базы и хранилища:
[docs/PROJECT_MAP.md](docs/PROJECT_MAP.md). Правила сопровождения: [AGENTS.md](AGENTS.md).

Добавляйте массивы вопросов в `src/data/questions/*.json`.
Файлы подключаются автоматически при сборке. Индексы `correctAnswers` начинаются
с нуля. ID должен быть уникальным среди всех файлов. Например:

```json
[
  {
    "id": "custom-001",
    "category": "Италия",
    "subcategory": "Пьемонт",
    "difficulty": "medium",
    "question": "Из какого сорта производят Бароло?",
    "options": ["Санджовезе", "Неббиоло", "Барбера", "Мерло"],
    "correctAnswers": [1],
    "explanation": "Бароло производят из Неббиоло.",
    "image": null,
    "sourceIds": ["barolo"]
  }
]
```

Картинки кладите в `public/illustrations/` и указывайте
`"image": "illustrations/file.jpg"`. Допустимы также HTTPS URL.
Предпочтительны локальные файлы для автономности и отсутствия внешнего трекинга.
Ошибки JSON, некорректные вопросы и дубли ID не ломают клиент: он показывает
предупреждение и пропускает их. CLI-проверка блокирует публикацию такой базы.

Каталог официальных материалов — `src/data/sources.json`. Добавляя новый источник,
укажите уникальный `id`, организацию (`organization`), название (`title`), HTTPS-ссылку
(`url`) и дату сверки (`checkedAt`, YYYY-MM-DD). Затем укажите его ID в `sourceIds`
вопроса. Поле совместимо со старым форматом и необязательно для внешних наборов,
но все вопросы поставляемой базы имеют источники. Проверка обнаруживает
неизвестные ссылки, повторные ID и небезопасные адреса.
Полный реестр 105 материалов с 30 сайтов и привязкой к каждой категории:
[docs/SOURCES.md](docs/SOURCES.md). Его нужно поддерживать при расширении базы.

Прогресс привязан к браузеру и адресу сайта. Очистка данных браузера удаляет его;
для переноса используйте экспорт. Хранилище не является защищённым: результаты
можно изменить вручную, экзамен предназначен для самопроверки. Ответы находятся
в статической сборке. Изменение базы требует повторного деплоя.
